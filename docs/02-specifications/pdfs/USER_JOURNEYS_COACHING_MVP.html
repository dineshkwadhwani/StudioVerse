1. How to use this document

Each journey is a self-contained scenario a tester can walk through. Journeys use the format:

  • Pre-conditions — what must be true before starting (signed-in role, fixture data, balance).
  • Steps — numbered click-through.
  • Expected outcomes — what should be visible after each meaningful step.
  • Edge cases to validate — variants worth probing within the same journey.

All journeys assume the Coaching Studio tenant. URLs use the pattern /coaching-studio/<route>.

3. Pre-test setup & test data

Before walking through journeys, prepare the following fixtures in studioverse-test:

  • 1 SuperAdmin (seeded)
  • 1 Coaching Studio tenant configured: opening treasury 100,000 coins; registration bonus 10; referral bonus 5; cashout min 100.
  • 1 Company user (self-registered)
  • 2 Professionals: one associated to the company, one independent
  • 2 Individuals: one associated to the company-coach, one self-registered
  • 1 published Program, 1 published Event, 1 published Assessment
  • 1 Promotion Package, 1 Bot Hero Package, 1 Coin Package, 1 Listing Package

Recommended phone numbers: use Firebase Auth test phones with fixed OTP 123456.

4. SA SuperAdmin journeys

SA-A. First-time platform setup

Pre-conditions: Seeded SuperAdmin account. No tenants exist yet.

SA-A1 · Sign in & land on SuperAdmin portal

  1. Visit /coaching-studio/auth and sign in with SA phone + OTP.
  2. Verify automatic redirect to SuperAdmin portal home (stats tiles render: tenants, users, programs, assessments, events).

Edge: Sign in with a non-SA phone — should land on regular dashboard, not SA portal.

SA-A2 · Create & configure a tenant

  1. Open Tenants tab in SA portal.
  2. Create tenant: slug coaching, name "Coaching Studio", description.
  3. Open the tenant's Wallet Config: set opening treasury 100,000; registration bonus 10; referral bonus 5; cashout min 100.
  4. Open Mail Config: enable, set sender noreply@coachingstudio.in, name "Coaching Studio".
  5. Open Bot Config: enable, persona "Coach Dinesh", message cap 5.
  6. Open Landing Config: toggle Programs / Events / Tools sections on.
  7. Open Lead Fees: enable Coach lead unlocking at 10 coins, Company at 20, Individual disabled.

Edge: Save with empty tenant slug — should error. Save with duplicate slug — should error.

SA-A3 · Create catalog content (Program / Event / Assessment)

  1. Open /coaching-studio/manage-programs → New Program → fill required fields (name, type, duration, credits) → Publish.
  2. Open /coaching-studio/manage-events → New Event → fill fields incl. city + date → Publish.
  3. Open /coaching-studio/manage-assessments → New Assessment → choose render style + report style → Publish.

Edge: Publish with missing thumbnail — flag if not blocked. Set availableFrom in future — verify it does not appear on landing until that date.

SA-A4 · Configure earning packages

  1. Open Earning Packages → Promotion Packages tab → create 2 packages (7-day at 50 coins, 30-day at 200).
  2. Bot Hero Packages tab → create 1 (30-day, 1000 coins).
  3. Coin Packages tab → confirm Starter / Player / Champion / Pro League / Titan rows seeded; toggle one inactive.
  4. Listing Packages tab → create 1 (basic listing, 14 days).
  5. Lead Fees tab → confirm values from SA-A2.

SA-B. Day-2 operations & approvals

SA-B1 · Approve a coach's promotion request

Pre: A Coach has submitted a Program promotion request.

  1. Dashboard → click "Pending Promotion Requests" tile.
  2. On Approve Requests page, Promotions tab is active — review request → Approve.
  3. Verify: program's promotionStatus becomes active; promoted-first ordering reflects on landing for Events (Programs gap noted).

Edge: Deny — verify request marked denied; coach's coin debit refunded; coach is notified.

SA-B2 · Approve a Bot Hero request

  1. Dashboard → "Pending Bot Hero Requests" tile.
  2. Review coach profile, durations, image; pick start date that doesn't overlap an active hero; Approve.
  3. Verify: status active at start date; treasury credited; bot widget overrides persona to coach name/avatar within window.

Edge: Try to pick a start date that overlaps another active/approved hero — should be blocked with clear error.

SA-B3 · Approve a cashout request

  1. Dashboard → "Pending Cashout Requests" tile.
  2. Verify request shows: requester, amount, payout details, current wallet balance.
  3. Approve — verify status approved; deduction visible in user's ledger.

Edge: Approve when requester wallet went below the requested amount after submission — should still hold the original debit (debit happened at request time).

SA-B4 · Manage users & wallets cross-tenant

  1. Open Users tab → filter by tenant + role; verify counts match dashboard.
  2. Open a Coach's row → Manage Wallet → see ledger including credits, debits, sent/received transfers.
  3. Issue an offline allocation of 500 coins to that coach with reason "manual_offline_allocation".

Edge: Try to assign coins exceeding treasury balance — should fail; verify treasury auto top-up triggers if configured.

SA-B5 · View & filter coin orders

  1. Open Orders page → filter by status paid, date range, role company.
  2. Verify totals match Monetization tiles on dashboard.

SA-B6 · Manage referrals platform-wide

  1. Open Referrals → tenant dropdown → switch to a specific tenant — list filters live.
  2. Click "Send reminder" on an outstanding referral — verify reminder logged and email triggered.

5. C Company journeys

C-A. Onboarding

C-A1 · Self-register as Company

  1. Visit /coaching-studio/auth.
  2. Phase 1 — phone + OTP. Phase 3 — pick role Company. Phase 4 — fill company details (name, position, GST optional).
  3. Verify: profile created; wallet auto-created; opening balance applied per tenant config; redirected to dashboard.

Edge: Use phone already registered — should sign in (not duplicate-create). Cancel during phase 4 — partial profile state visible to user; eligibility flags reflect incompleteness.

C-B. Build the team

C-B1 · Onboard a coach (Professional) under the company

  1. Open /coaching-studio/manage-users → Add User → role Professional.
  2. Enter coach's phone, name, email; submit.
  3. Verify: coach created with associatedCompanyId = your uid; coach's wallet exists with 0 opening (company-onboarded coaches don't get registration bonus).

Edge: Add coach with phone already on platform under another tenant — should error or warn. Add as Individual (different role) — verify scoped behavior.

C-B2 · Onboard an Individual under the company (direct)

  1. Add User → role Individual → enter details → submit.
  2. Verify: individual created with associatedCompanyId = company; wallet auto-provisioned; appears in Manage Users list.

C-B3 · Build a cohort & assign content

  1. Open /coaching-studio/manage-cohorts → New Cohort → name, professionalId (one of the company's coaches), add ≥2 individuals.
  2. Save → verify cohort status becomes active.
  3. Open the cohort detail → Assign Activity → pick a published Program → confirm.
  4. Verify: wallet deducts (members × creditsRequired); each individual sees the assignment in their My Activities; assignor sees in Assigned Activities.

Edge: Insufficient wallet → company sees "Insufficient credits" gate; no partial creation. Cohort with 1 member → status remains inactive; assignment blocked. Add a member, retry.

C-C. Coin operations & approvals

C-C1 · Buy coins (placeholder payment)

  1. Open /coaching-studio/buy-coins → pick the Champion package → Confirm Order.
  2. On placeholder payment screen → Simulate Success.
  3. Verify: order moves created → pending → paid; wallet credited; ledger entry visible.

Edge: Click Simulate Failure instead — order remains pending; wallet not credited; idempotency holds (retry success → only one credit).

C-C2 · Approve a coach's coin request

Pre: An associated coach has submitted a coin request.

  1. Open /coaching-studio/manage-wallet → Coin Requests tab/modal.
  2. Open the pending request → review amount & reason → Approve.
  3. Verify: company wallet debited; coach wallet credited; two ledger entries appear (sent + received); request marked approved.

Edge: Deny → coach is refunded the credits originally held at request time. Approve when company has insufficient balance — should block with message.

C-C3 · Cashout idle credits

  1. Open Manage Wallet → Cashout → enter amount ≥ tenant minimum → submit payout details.
  2. Verify: amount debited immediately (held); request listed under "Cashout History" as pending; SuperAdmin sees it in approvals queue.

C-D. Visibility & reports

C-D1 · See team & assignment activity

  1. Open /coaching-studio/assigned-activities → see assignments you created.
  2. Open Manage Users → confirm associated coaches/individuals listed.
  3. Open dashboard → see your activity completion stats (own).

6. P Professional (Coach) journeys

P-A. Onboarding (independent vs company-associated)

P-A1 · Self-register as independent Coach

  1. Visit auth page → phase 3 select Professional.
  2. Phase 4 fill credentials, certifications, headline, bio, profile photo.
  3. Verify: registration bonus credits applied; wallet created; associatedCompanyId is null (independent).

Edge: Skip optional fields — profile completion % < 100; assignmentEligible may be false if mandatory fields missing.

P-A2 · Get added as a company-associated coach

  1. Company onboards you (see C-B1).
  2. Sign in for the first time → verify associatedCompanyId visible on profile.
  3. Verify: wallet has 0 balance (no registration bonus for company-onboarded coaches).

P-B. Manage learners & cohorts

P-B1 · Onboard an Individual under the coach

  1. Open /coaching-studio/manage-users → Add User → role Individual.
  2. Submit — verify individual created with associatedProfessionalId = your uid.

P-B2 · Build a cohort & assign

  1. Open /coaching-studio/manage-cohorts → New Cohort → add ≥2 individuals → save → status active.
  2. From cohort detail → Assign Program → confirm — wallet deducts members × cost.

Edge: Try to remove members below 2 — cohort drops to inactive.

P-C. Create & promote content

P-C1 · Create a Program (when feature available)

Note: per audit, Coach-side Program creation UI is a known gap; SA path tested in SA-A3.

P-C2 · Request promotion of an existing Program/Event

  1. Open the program/event detail → Request Promotion.
  2. Pick a Promotion Package → confirm (credits debited).
  3. Verify: request appears in your "My Requests" list as pending; SA sees it in approval queue.

Edge: Insufficient credits → blocked. SA denies → credits refunded.

P-C3 · Submit a Bot Hero request

  1. Open /coaching-studio/promote-coach → pick package → preferred start date → submit.
  2. Verify: request marked pending; credits debited; request visible in your history.

Edge: Submit without profile photo — should be blocked with message. SA denies — credits refunded.

P-D. Coin operations

P-D1 · Request coins from your company

Pre: You are company-associated. Independent coaches cannot use this flow.

  1. Open /coaching-studio/request-coins → enter amount + reason → submit.
  2. Verify: request appears in your history as pending. Company sees it in their Coin Requests modal.

P-D2 · Buy coins (independent coach)

  1. Open Buy Coins → pick package → simulate success → wallet credits.

P-D3 · Cashout earnings (independent only)

  1. Open Manage Wallet → Cashout → amount ≥ tenant minimum → submit.
  2. Verify: pending request visible; SA can approve.

Edge: Company-associated coaches: cashout option should be hidden — earnings route to company wallet (verify via creator-earnings ledger).

P-E. Visibility

P-E1 · Use Search & lead unlocks

  1. Open /coaching-studio/search → search for "leadership" → filter Programs.
  2. Filter Individuals → see lead tiles. If Coach lead-fee enabled, your tile may appear locked to viewers; switching role you see Individuals as locked tiles to be unlocked.
  3. Click an Individual tile → if locked, Unlock → confirm fee debit → tile becomes unlocked & persists.

Edge: Try unlock when wallet balance < fee — blocked. Re-open the tile — already unlocked, no re-charge (idempotent).

P-E2 · Send an intro message

  1. From an unlocked Individual lead tile → Send Message → choose template (T1 standard or T2 personalized).
  2. Send → verify in your Outbox.
  3. Recipient sees the message unlocked (Coach→Individual messages arrive unlocked).

Edge: Send second message to same recipient — duplicate state shown; no second debit.

7. I Individual journeys

I-A. Onboarding

I-A1 · Self-register as Individual

  1. Visit auth page → phase 3 → Individual.
  2. Phase 4 — name, email, basic profile.
  3. Verify: registration bonus credits applied; wallet created; redirected to dashboard.

I-A2 · Auto-provisioned during assignment

Pre: A Coach has assigned a program/event/assessment to your phone before you registered.

  1. Visit auth page → register with the same phone.
  2. Verify: profile created; existing assignment now linked to your uid; previously-stamped userId on attempt/report is reconciled (per recent rule fix, you can read the assignment-linked report once your auth uid matches).

Edge: Legacy assignments where userId on report is the assignment's pre-auth assigneeId — current rule allows read via assignment.assigneeId match (verified May 9 fix).

I-B. Take an activity

I-B1 · Discover an assignment in My Activities

  1. Open /coaching-studio/my-activities.
  2. Verify the freshly-assigned program/event/assessment is visible with status assigned.

I-B2 · Complete an assessment & view report

  1. Open the assigned assessment → click Start.
  2. Walk through the questions (e.g., SingleChoice / Likert / Slider variants per render style).
  3. Submit — verify "report being prepared" state.
  4. After ~30s, refresh — open the report from My Activities.
  5. Verify: report sections render per chosen template; assessment status moves to completed; coach (assignor) can see completion in their Assigned Activities view.

Edge: Mid-quiz refresh — verify in-progress preservation if implemented; otherwise, attempt restarts. Verify report read access for the coach (assigner) and the company (if assignor was company).

I-B3 · Mark a Program/Event in progress and complete

  1. From My Activities → open assignment → mark In progress.
  2. Later → mark Complete. Verify state transitions and assignor visibility.

I-C. Discovery & messaging

I-C1 · Discover a Coach in Search

  1. Open Search → choose "Coaches" category → enter keyword.
  2. Verify: Coaches whose Name / Headline / Bio / Credentials match appear; tiles unlocked (Individual viewing Coach is always unlocked since Individual lead-fee disabled or N/A).

I-C2 · Send intro message to a Coach

  1. From a coach tile → Send Message → use the Individual template.
  2. Verify: message lands in coach's Inbox locked (Individual→Coach is gated).

Edge: Send second time to same coach — duplicate state, no second debit.

I-D. Wallet

I-D1 · See own wallet & transactions

  1. Open Manage Wallet → verify ledger entries: registration bonus, any debits/credits.
  2. Verify Buy Coins is available; cashout option is hidden for Individuals.

I-D2 · Refer a friend

  1. Open Manage Referrals → invite a friend by phone/email.
  2. Friend joins (registers) → verify both sides are credited per tenant config (joiner gets registration bonus; referrer gets referral bonus).

8. Cross-role end-to-end scenarios

These tie multiple roles together — useful for regression sweeps and demo flows.

E2E-1 · Company onboards coach & individuals → assigns assessment → coach reviews report

  1. SA seeds tenant + 1 published assessment.
  2. Company registers, onboards a coach (P) and 3 individuals.
  3. Company creates a cohort with the 3 individuals + coach → assigns the assessment.
  4. Each Individual takes the assessment → reports generate.
  5. Coach opens Assigned Activities → sees status of all 3 individuals → opens their reports (assigner read).
  6. Company opens dashboard — sees activity completion summary.

E2E-2 · Coach Bot Hero monetization end-to-end

  1. SA creates a Bot Hero package (30 days, 1000 coins).
  2. Coach tops up wallet (Buy Coins) → submits Bot Hero request → preferred start tomorrow.
  3. SA approves, picks tomorrow as start.
  4. Move clock forward (or wait) → bot widget on landing now reflects coach name & avatar.
  5. At end date → bot widget reverts to tenant default persona; coach's hero status moves to expired.

E2E-3 · Coin transfer (company → coach) and ledger reconciliation

  1. Coach (company-associated) requests 500 coins.
  2. Company approves the request.
  3. Verify: company wallet debited 500; coach wallet credited 500; two ledger entries (sent + received) — request marked approved.
  4. SA opens both wallets in admin view → ledger totals reconcile; treasury unaffected.

E2E-4 · Promotion request → approval → landing-page promoted-first ordering

  1. Coach publishes an event & requests promotion.
  2. SA approves.
  3. Visit landing page (signed-out) → verify promoted event surfaces ahead of non-promoted ones.
  4. After expiry → ordering returns to default.

E2E-5 · Lead unlock + intro message paid path

  1. Coach searches Individuals → tile is locked (lead fee > 0) → unlocks (debit).
  2. Coach sends T2 personalized intro message → message lands in Individual's Inbox unlocked.
  3. Individual replies-in-kind by sending intro to the coach → message lands in coach Inbox locked until coach pays unlock fee.

E2E-6 · Cashout & treasury reconciliation

  1. Coach earns from creator-attribution flow (assignment from another tenant member to their content).
  2. Coach requests cashout ≥ minimum.
  3. SA approves — verify ledger debit on coach wallet; treasury counters update; cashout-to-purchase ratio tile reflects.
