## 1. Purpose

This epic extends the StudioVerse taxonomy framework from a 2-tier model (Category → Sub Category) to a 3-tier model (Category → Sub Category → Topic).

The taxonomy provides a structured way to classify platform content (Programs, Assessments, Events) at multiple levels of granularity, enabling better discoverability, search relevance, and content curation across all studios.

---

## 2. Taxonomy Data Model

### 2.1 Hierarchy

```
Category
  └── Sub Category (parentId = Category.id)
        └── Topic (parentId = SubCategory.id + Category.id)
```

Each level is scoped by `tenantId`. Content resources may reference any number of topics via `topicIds: string[]`.

### 2.2 Firestore Collections

| Collection       | Key Fields                                                                      |
|------------------|---------------------------------------------------------------------------------|
| `categories`     | `id`, `tenantId`, `tenantName`, `name`, `description`, `createdBy`              |
| `subCategories`  | `id`, `tenantId`, `tenantName`, `categoryId`, `categoryName`, `name`, `description` |
| `topics`         | `id`, `tenantId`, `tenantName`, `categoryId`, `categoryName`, `subCategoryId`, `subCategoryName`, `name`, `description` |

### 2.3 Topic Document Fields

| Field               | Type     | Description                                     |
|---------------------|----------|-------------------------------------------------|
| `id`                | string   | Auto-generated Firestore document ID            |
| `tenantId`          | string   | Owning tenant                                   |
| `tenantName`        | string   | Denormalized tenant name                        |
| `categoryId`        | string   | Parent category                                 |
| `categoryName`      | string   | Denormalized category name                      |
| `subCategoryId`     | string   | Parent sub category                             |
| `subCategoryName`   | string   | Denormalized sub category name                  |
| `name`              | string   | Topic display name                              |
| `description`       | string   | Optional description                            |
| `createdBy`         | string   | UID of creator                                  |
| `updatedBy`         | string   | UID of last updater                             |

## 3. Admin Interface — Manage Categories Page

### 3.1 Tabs

The Manage Categories page (`/[studio]/manage-categories`) has three tabs:

1. **Category** — Create and edit categories (tenant-scoped)
2. **Sub Category** — Create and edit sub categories (linked to Category)
3. **Topic** — Create and edit topics (linked to Sub Category)

### 3.2 Topic Tab Behavior

- Tenant selector shows all active tenants (SuperAdmin view).
- Category dropdown is filtered by the selected tenant.
- Sub Category dropdown is filtered by the selected tenant and selected Category.
- Name and Description fields complete the form.
- Saved topics appear in a filterable table showing Tenant, Category, Sub Category, Name, and Description.
- Edit button pre-populates the form for updates.

---

## 4. Resource Integration

### 4.1 Programs

- Program create/edit forms include a multi-select Topics field.
- Program create/edit forms include a Competency Level dropdown.
- Topics shown as checkbox-pills.
- Topics are filtered by the program's selected `tenantId` and `subCategoryId`.
- Changing Sub Category resets Topic selection.
- `topicIds: string[]` persisted to Firestore and through `createProgram` / `updateProgram` Firebase Functions.
- `competencyLevel: number` persisted to Firestore and through `createProgram` / `updateProgram` Firebase Functions.

### 4.2 Assessments

- Assessment create/edit forms include a multi-select Topics field.
- Assessment create/edit forms include a Competency Level dropdown.
- Same filtering and reset behavior as Programs.
- `topicIds: string[]` persisted to Firestore and through `createAssessment` / `updateAssessment` Firebase Functions.
- `competencyLevel: number` persisted to Firestore and through `createAssessment` / `updateAssessment` Firebase Functions.

### 4.3 Events

- Event create/edit forms include a multi-select Topics field.
- Event create/edit forms include a Competency Level dropdown.
- Same filtering and reset behavior as Programs.
- `topicIds: string[]` persisted to Firestore and through `createEvent` / `updateEvent` Firebase Functions.
- `competencyLevel: number` persisted to Firestore and through `createEvent` / `updateEvent` Firebase Functions.

### 4.4 Tenant Competency Framework Selection

- SuperAdmin tenant create/edit now includes a `Competency Framework` section.
- The framework dropdown lists seeded competency documents for the selected tenant.
- The selected framework is stored on the tenant document as `competencyFramework.{competencyId, competencyName}`.
- Resource forms resolve level labels from that tenant selection while storing only numeric levels in the resource document.
- If no framework is selected, resource forms fall back to a default `Level 1` to `Level 5` scale.

## 6. Service Layer

### 6.1 `src/services/categories.service.ts`

- `listTopics(): Promise<TopicRecord[]>` — Reads all documents from the `topics` Firestore collection.
- `saveTopic(form: TopicFormValues, createdBy: string): Promise<void>` — Creates or updates a topic document. Denormalizes `tenantName`, `categoryName`, `subCategoryName` from the loaded data at save time.

---

## 7. Firebase Functions

### 7.1 Schema Updates

All three resource schemas (`assessmentWriteSchema`, `programWriteSchema`, `eventWriteSchema`) now include:

```typescript
topicIds: z.array(z.string().trim()).optional().default([])
competencyLevel: z.number().int().min(1).max(5).default(1)
```

### 7.2 Firestore Mapper Updates

The `toFirestore*Data` functions in each schema file include `topicIds: input.topicIds ?? []` in the output.

---

## 8. UI Pattern — Topic Checkbox Pills

Topics are presented as pill-shaped checkbox toggles in forms:

- Unselected: outlined pill with neutral background
- Selected: filled pill with `#1b4159` (platform blue) background and white text
- Pills are rendered when a Sub Category is selected and topics exist for that tenant + sub category combination
- Pills are hidden when no topics exist for the current selection

---

## 9. Backward Compatibility

- Existing Programs, Assessments, and Events without `topicIds` fields are not migrated automatically.
- Existing Programs, Assessments, and Events without `competencyLevel` are not migrated automatically.
- All mappers treat a missing `topicIds` field as an empty array (`[]`).
- All mappers and form state treat a missing `competencyLevel` as `1`.
- No breaking changes to existing Firestore schemas.

---

## 10. Deployment Notes

- The `topics` Firestore collection is new. Firestore security rules must allow authenticated reads on the `topics` collection (same pattern as `categories` and `subCategories`).
- Tenant competency framework selection reads from the existing `competency` collection and writes the selected framework metadata onto `tenants` documents.
- Firebase Functions for assessments, programs, and events must be redeployed after these schema changes.
- No index changes are currently required for the `topics` collection.
