# StudioVerse

## Functional Specification Document

## Categories and Sub Categories Management

**Epic ID:** E17  
**Document Version:** 1.0  
**Date:** May 2026  
**Classification:** Confidential

---

## 1. Document Purpose

This document defines Epic E17 for StudioVerse. The epic introduces platform-level Category and Sub Category collections and a SuperAdmin-only management experience to maintain these taxonomy records.

The taxonomy is tenant-scoped and is used as metadata attributes for Programs, Events, and Assessments.

---

## 2. Epic Objective

The objective of E17 is to deliver:

- Two new Firestore collections: `categories` and `subCategories`.
- A new SuperAdmin menu item under the Manage group: Categories.
- A tabbed Manage Categories page with two tabs:
  - Category
  - Sub Category
- Category CRUD fields:
  - Tenant (dropdown)
  - Category Name
  - Category Description
- Sub Category CRUD fields:
  - Tenant (dropdown)
  - Parent Category (dropdown from Category records)
  - Sub Category Name
  - Sub Category Description
- Resource attribute integration so Programs, Events, and Assessments store selected category and sub-category values.
- Firestore rule updates enforcing SuperAdmin-only write access for taxonomy collections.

---

## 3. Scope

### 3.1 In Scope

- `categories` collection for tenant taxonomy parent nodes.
- `subCategories` collection for child taxonomy nodes linked by `categoryId`.
- SuperAdmin portal menu update to expose Categories management in the Manage group.
- Tabbed category management page in admin area.
- Category and sub-category dropdowns added to:
  - Program create/edit forms
  - Event create/edit forms
  - Assessment create/edit forms
- Persistence of `categoryId`, `categoryName`, `subCategoryId`, and `subCategoryName` on resource documents.

### 3.2 Out of Scope

- Bulk import/export for categories.
- Soft-delete/archive lifecycle for category records.
- Localization/multi-language taxonomy labels.

---

## 4. Security and Access Rules

- Only SuperAdmin users can create/update category and sub-category records.
- Signed-in users may read category and sub-category records for form selection and filtering.
- Rule entries introduced:
  - `match /categories/{categoryId}`
  - `match /subCategories/{subCategoryId}`

---

## 5. Data Model

### 5.1 categories

Recommended fields:

- `tenantId` (string)
- `tenantName` (string, optional snapshot)
- `name` (string)
- `description` (string)
- `createdAt` (timestamp)
- `updatedAt` (timestamp)
- `createdBy` (string)
- `updatedBy` (string)

### 5.2 subCategories

Recommended fields:

- `tenantId` (string)
- `tenantName` (string, optional snapshot)
- `categoryId` (string)
- `categoryName` (string)
- `name` (string)
- `description` (string)
- `createdAt` (timestamp)
- `updatedAt` (timestamp)
- `createdBy` (string)
- `updatedBy` (string)

### 5.3 Resource Attribute Fields

Programs, Events, and Assessments carry:

- `categoryId`
- `categoryName`
- `subCategoryId`
- `subCategoryName`

---

## 6. UI Requirements

### 6.1 SuperAdmin Navigation

- Add `Categories` menu item to the Manage group in SuperAdmin portal.

### 6.2 Manage Categories Page

- Header/title: Manage Categories.
- Tabs:
  - Category
  - Sub Category

### 6.3 Category Tab

- Form inputs:
  - Tenant
  - Name
  - Description
- List table with tenant, name, description, and edit action.

### 6.4 Sub Category Tab

- Form inputs:
  - Tenant
  - Category dropdown (loaded from categories for the selected tenant)
  - Name
  - Description
- List table with tenant, parent category, name, description, and edit action.

---

## 7. Implementation Notes

- Taxonomy records are tenant-scoped using `tenantId`.
- Category and sub-category options are filtered by selected tenant in resource forms.
- Sub Category options are filtered by selected Category within the selected tenant.
- Resource form save flows persist both IDs and label snapshots.
- Callable validation schemas for Program/Event/Assessment accept the new taxonomy fields.

---

## 8. Deployment Notes

- Firestore rules must be deployed to production after taxonomy rules are added.
- Frontend and functions deployments should be promoted so new resource attributes are accepted and saved end-to-end.

---

## 9. Acceptance Criteria

- SuperAdmin can open Manage -> Categories.
- Category tab supports create and edit with tenant, name, description.
- Sub Category tab supports create and edit with tenant, parent category, name, description.
- Programs, Events, and Assessments can save selected category/sub-category values.
- Non-superadmin users cannot write to `categories` or `subCategories`.
- Production Firestore rules include category/sub-category access policy.
