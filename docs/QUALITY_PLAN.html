1. Purpose & scope

This Quality Plan defines how the StudioVerse Coaching Studio MVP is verified before each promotion from studioverse-test to studioverse-prod, and how ongoing regression is managed through the post-MVP roadmap.

It is the operating manual for the QA function: tooling, environments, test strategy, defect handling, entry/exit gates, and metrics. It complements:

  • USER_JOURNEYS_COACHING_MVP.html — narrative role journeys.
  • TEST_CASES.md — atomic, bifurcated test cases (automatable vs manual).
  • ROLE_RESPONSIBILITY_MATRIX.html — capability matrix per role.
  • FIREBASE_PROD_ROLLOUT_RUNBOOK.md — operational steps for rules / functions deployment.

3. In-scope / out-of-scope

In scope

  • Coaching Studio MVP for all four roles (SA, Company, Coach, Individual).
  • Firestore rules, Firebase Functions, Next.js App Router routes under /coaching-studio/*.
  • Resend email delivery, Groq AI report generation, Firebase Auth (phone OTP).
  • Vercel preview deploys + studioverse-test Firebase project.

Out of scope (until separately scoped)

  • Training Studio & Recruitment Studio specific flows (covered by separate plans when introduced).
  • Capacitor / native app wrapping (not built).
  • Real Razorpay integration (placeholder payment in MVP).
  • Marketplace commission split (planned).
  • Load testing & chaos engineering (post-MVP — covered by performance plan).

10. Defect management

Severity

SevDefinitionResolution SLA (test env)Resolution SLA (prod)
P0Production blocker; data loss; payment/wallet incident; widespread auth failure.4h2h hotfix
P1Major feature broken; no workaround; affects multiple roles.1 business day1 business day
P2Single feature broken; workaround exists.Next sprintNext sprint
P3Cosmetic, copy, minor UX.Backlog (committed quarterly)Backlog

Lifecycle

  1. New — reported with environment, role, repro steps, expected vs actual, screenshots/logs.
  2. Triaged — severity assigned, owner assigned (within 1 business day).
  3. In progress — owner working; failing test exists for P0/P1.
  4. Fixed — PR open with test; awaiting review.
  5. Verified — QA replays original repro on the fix branch's preview.
  6. Closed — merged + deployed; regression test in place for P0/P1.
Production-incident rule: any P0 in studioverse-prod requires (a) an incident note appended to FIREBASE_PROD_ROLLOUT_RUNBOOK.md, (b) a regression test added to the suite before close, and (c) a 1-page postmortem within 48h.

11. Entry / exit criteria

Entry to QA cycle (per release branch)

  • All planned features merged to release branch.
  • Unit + lint + typecheck green on CI.
  • Test fixtures refreshed on studioverse-test.
  • Smoke test script runnable against the preview URL.

Exit (release ready)

  • 0 P0 / P1 open.
  • Regression suite green (including May 2026 fixes: wallet credit, assessment report read, walletTransactions list).
  • Manual checklist signed: visual smoke (desktop + mobile), accessibility spot-check, email smoke (one per category).
  • Prod-deploy runbook updated with any rules / function / env changes.
  • Performance budget met (landing TTI < 3s p95).

14. Open risks & assumptions

  • Real PSP integration pending — Buy Credits is placeholder. Wallet-crediting branch is tested via simulate-success, but real Razorpay webhooks and idempotency must be re-tested when introduced.
  • Listing fee / commission split not implemented — out of scope; revisit when E14 phase 2 lands.
  • Route-level role guards absent — direct-URL access to authenticated pages is currently menu-hidden, not server-blocked. Rules enforce data access, but UI strings/components may render. Tracked as a non-blocking risk for MVP.
  • Bot endpoints not rate-limited — abuse risk; recommend Cloud Functions IP-rate limit before opening to wider audience.
  • Two parallel auth flows (AuthWizard + LoginRegisterModal) — only AuthWizard calls saveUserProfile(). Tests must fix the auth path used; bug risk for users registered via the modal path.
  • Treasury txn read no longer gated client-side (May 10 rule fix) — accepted trade-off; treasury wallet doc remains SA-only. Re-evaluate when separating treasury txns into a distinct collection.
  • AI provider drift — Groq llama-3.3-70b. Output coherence depends on the underlying model; track manual quality reviews per release.
  • Test phone allotment — Firebase test phones are shared across environments; coordinate to avoid OTP collisions.

15.2 Per-release smoke checklist (manual, ~30 min)

  1. Sign in as Company → onboard a Coach + 2 Individuals → create cohort → assign assessment.
  2. Sign in as Individual → take assessment → see report.
  3. Sign in as Coach (company-associated) → request 200 coins.
  4. Sign in as Company → approve coin request → confirm both wallets & ledger.
  5. Sign in as Coach (independent) → submit Bot Hero request.
  6. Sign in as SA → approve Bot Hero → land on landing → confirm widget persona.
  7. Sign in as Coach → search Individuals → unlock a lead → send T2 intro.
  8. Sign in as Individual → see unlocked message in inbox.
  9. Sign in as Coach → request cashout (independent only).
  10. Sign in as SA → approve cashout → confirm ledger.
  11. Visit landing signed-out → confirm promoted-first ordering.
  12. Spot-check email inbox: 1 assignment-created, 1 coin-request-approved, 1 cashout-pending.
